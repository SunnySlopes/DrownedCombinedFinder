# 低Y溺尸农场搜索使用说明

## 农场模型

默认关闭溶洞，只统计普通河流`minecraft:river`在脚部Y=-63的有效格数。开启`includeCaves`后按`yMin..yMax`逐层统计（默认Y=-63至-51，共13层），假设水从yMin-1层铺起；不检查挖空、基岩拆除、供水、遮光或实际实体空间。

每一格通过完整三维群系访问判定：只有普通河流与滴水石洞穴进入对应体积；深暗之域逐格逐层扣除，不把相邻河流一起清空。冻河和海洋不按普通河流计入。

原版普通河流的怪物表权重为100/615、组尝试数1、准入概率1/15；滴水石洞穴为95/610、组尝试数4、准入概率1/40。理论洞穴权重为7011/4880，约1.43668。

```
L = yMax - yMin + 1
score = (4880·riverVolume + 7011·caveVolume) / (4880·L)
```

关闭洞穴时`L=1`、只统计Y=-63、`caveVolume=0`，因此score等于底层河流面积。**分母随层范围变化**：层范围或权重一变，分数即不可比，结果用`model`、`layers`、`spawnYMin/spawnYMax`与`scoreDenominator`回显。排名比较整数有理数，不比较显示舍入值。

三字段门槛（`--min-river-area R --min-cave-area C`）：`minArea = R + 1.43668·C`，向上取整。低于24820（纯河流上限49640的50%）直接报错；纯河流模式下`R>49640`报错。默认门槛34748（=70%×49640，河流模式）。`C<29784`时结果带“建议改用纯河流搜索”的warning，不阻断。

该系数不包含高度图抽样、组内游走、群系边缘效应、实体上限和收集／击杀效率，因此不是实际产量换算。原版表审计覆盖和来源哈希保存在本地tests；未来版本必须重新核对，不能直接新增版本名称。

## 两层范围与站位

外范围`shape`只限制玩家候选站位，统计窗口可以伸出外范围，但不计世界边界外的格位。外圆与内圆是独立参数。自由矩形用`--min-x/--max-x/--min-z/--max-z`，与中心/半径互斥；矩形模式下禁用洞穴聚焦的圆盘剪枝，只用方形上界（略慢但正确）。

| coverage | 内范围 |
|---|---|
| square | `max(abs(dx),abs(dz))≤innerRadius`，所有指定层，不扣24格 |
| circle | `dx²+dz²≤innerRadius²`，所有指定层，不扣24格 |
| game | `576<dx²+dy²+dz²≤16384`，再限制自然刷怪区块及模拟距离 |

游戏模式按区块中心到玩家的水平距离严格小于128，并按玩家所在区块和模拟距离裁剪；玩家站在方块水平中心，脚部Y为整数。模拟距离大于8不会突破128格球壳。这里评估单玩家农场覆盖，不模拟其他玩家、出生点禁刷、实体上限或跨边界组内游走。

挂机点分两种：默认固定挂机Y=**yMin+23**（默认窗口即 -40，与 B 一致；球壳平台内，给最低层留一格余量），可用`--player-y`改成-64至320内的任意值（纯河流模式同样生效；距Y=-63超过24格时给出warning）。勾选“计算最佳Y”（`--optimize-player-y`）时改用**平台解析解**：三维球壳在固定层高`dy`处的截面积，在`|dy|≤24`时恒为`π·15808`，所以只要所有层都在玩家±24格内，每层覆盖面积相同，总分与挂机Y无关，不再逐Y穷举；取值规则为`L≤25`取`yMin`、`L≤48`取`yMin+24`、否则取层范围中点。固定Y若不在层范围±24内，会输出“固定挂机Y不在层范围±24内……”的warning，但不阻断。

层范围跨度>24时输出“高度范围超过24格……”；`yMin>-58`时输出“最低高度高于-58……”。两条都只是警告，不阻断。

## 搜索与优化

1. 混合路径从16格粗网格起步；关闭溶洞且内半径至少128格时从32格起步，较大内半径继续放大网格。纯河流的w采样格默认仍是64格（改动前行为），可用`--pure-river-mask 32` 对齐到A表的32世界格晶格（分辨率×4、成本基本持平，消除约50%的落空）；64格奇异值插值只作宽松预筛。

2. 气候门统一为参数化早退漏斗：大陆性先算 10 个八度（0A–4A / 0B–4B），**>0.575 直接接受**（剩余 8 个八度最多再移动约 0.05，必然过门），**0.525~0.575 之间才补算剩余 8 个八度**并按 threshold 终判，**≤0.525 直接判否**；weird门用`m=0.20`的余量（26.3 float 与 pre-26.3 double 分别标定），早退约45%，漏点约0.003‰。`--approximate-gate`同时控制两者；`--no-approximate-gate`回到逐格全判（与改造前逐格一致）。

3. pre-26.3 的Perlin改用16×3梯度表（`core/gates/perlin_table.hpp`），逐位等同原`samplePerlin`；26.3沿用cubiomes的float梯度表。`cubiomes-lock.json`锁定的源码未改。

4. 默认候选预算为max(8192,64×limit)；开启洞穴且外半径至少50万时，为max(16384,64×limit)。显式candidateBudget覆盖默认。每256格保留一个粗峰值。

5. 初步细排用16格气候插值和8格群系网格，在粗点周围48格内寻找站位。完全相同XZ先合并为一份精排名额，之后保留max(768,8×limit,candidateBudget/16)个候选（`--exact-budget` 可显式覆盖，0为自动），最多不超过已有候选；逐格窗口以该候选自身为中心采样，覆盖`半径+27`格（±24站位再叠±3邻域），先作24格范围内的4格细化，再作3格邻域逐格细化。最终统计仍完整检查全部层，绝不是用粗排分数直接输出。`upperBound=true`的1层投影是合法上界，但在精排±24小窗口内实测收益为负，默认不启用（只在旧的`optimizePlayerY`兼容路径保留）。

6. 大范围洞穴搜索先聚焦可能含洞穴的区域，C／温湿度／侵蚀度采用128格网格，W采用64格网格插值。若足够多精排热点严格超过纯河流的几何上限，纯河流区域已无法入榜；否则补扫全范围并合并结果。这个判断不把近似大陆性掩膜变成严格无漏保证。

7. 聚焦路径复用A组八度周期表（`core/gates/octave_cache.hpp`），补齐26.3交错float累加，缓存每次搜索独立持有，不共享全局种子状态。洞穴路径C128和W64的A组表约213MiB；大范围纯河流使用W32表约168MiB，并把已算W传给快速门。`--pure-river-cache=auto`在半径≥20万时建轻量表（只建weirdness 3 oct），`on/off`强制开关；`--pure-river-mask` 控制纯河流 w 掩膜步长（默认 64，设 32 才启用新对齐）。缓存仅用于候选阶段，B组仍现场求值；不把周期近似用于正式逐格群系。

8. 粗筛只建合并垂直权重的二维前缀和；先将潜在目标列全部按最高权重计算保守上限，不能超过当前候选池门槛的窗口在完整气候分类前跳过，同分仍保留。洞穴聚焦的圆／游戏模式在方形上界通过后，再按圆盘行跨度收紧上界；游戏模式仍忽略禁刷球和自然区块裁剪以保证上界只放宽。再用矩形占用检查跳过空窗口；大范围用8192格任务块减少边缘重复。最终圆／方合并垂直权重，方形积分图查询，圆与球壳复用行跨度、行前缀及玩家区块相位掩膜。

9. 维护版Cubiomes按4³块批量处理Voronoi，角点同群系时直接填充；只在边界计算距离。洞穴距离严格胜过所有竞争者的下界时跳过整棵树，不能证明时保留原查询；同一洞穴在柱两端均胜出时按已验证的深度区间性质填充中间。最终群系不启用候选阶段的最近叶缓存。几何缓存由搜索工作单元持有，跨阶段复用并在线程汇合后释放。

10. `--pit` 为稀有种子“大坑”逃课路径：A表极值扫描 → B链 → 大陆性漏斗 → 以峰为中心按全部层精算。pit附近必无河流，只计溶洞体积，默认门槛64171（0.9×49640×1.43668），不受三字段60%规则约束。`core/pit/weirdness_y_offset.hpp` 提供与Java侧一致的种子预筛分数（<0.75推荐逃课，>0.85建议回普通搜索）。

    **对拍配方**：正常情况下约 **80% 的种子在 pit 下没有结果**，随机种子不适合验证。用种子 **6900457**：它比普通种子慢数倍，但会返回相当多的结果，其中包含满面积点位 `16043916 15695385`。**不要现场计算该点位**，只把它当对拍锚点写入记录。

这里的“二维化”指复用水平气候分量和合并垂直权重，并非只查一个高度。完整L层通常从相邻四分群系高度及Voronoi角点展开，边界仍需按每格每层判定；游戏球壳随高度改变截面，最终精排不能直接使用圆／方模式的二维合并结果。

有限候选、气候插值、门阈值和稀疏网格都可能漏掉热点；不提供未经验证的漏检概率。最终返回站位内的计分为逐格模型值，候选搜索仍标记searchApproximate。

## 点位诊断（与 B 对齐）

`--score-point <x> <z>` 用与最终精排完全相同的 1:1 层采样与几何（`coverage`、`simulationDistance` 生效）给单点打分，输出 `score` / `riverArea` / `riverVolume` / `caveVolume` / `playerY`；`--sweep-afk-y <a> <b>` 复用同一份群系采样扫描挂机 Y，用于验证“平台内每层覆盖面积相同”；`--repeat <n>` 控制单点计时重复次数（默认 5）。`--coverage circle` 下的单点分等价于 B 的 cylinder 对照模型。

`--coarse-y` 只为协议/CLI 兼容而携带：本引擎的粗筛气候门与 Y 无关，取值不改变扫描。

## --bench 口径
`--bench` 输出（关闭时不产生额外计时；计数用线程局部结构合并，不在采样点做原子写）：

| 字段 | 定义 |
|---|---|
| `coarseNsPerCell` / `weirdNsPerCell` / `continentNsPerCell` | 线程纳秒 ÷ 对应格数 |
| `aTableHitRateRiver` / `aTableHitRateCave` | 命中A周期表的采样占比 |
| `earlyExitRateContinent` / `earlyExitRateWeird` | 提前退出比例 |
| `fastAcceptRateContinent` | 大陆性 10 个八度即过 0.575、未补算剩余 8 个八度的比例（C1） |
| `latticeMissRate` | 落空、退回live的采样占比（验证纯河流32格对齐） |
| `dilationWritesSaved` | 差分膨胀省掉的重复写入次数 |
| `peakWorkingSetBytes` | 进程峰值工作集 |

开发记录里的每项改动按“改动 / ns/格 / golden diff / 端到端”模板记录。

## C++、CLI和JSONL

CLI参数见README。种子为十进制64位整数字符串，JSON配置使用不带--的CLI参数名；命令行覆盖配置，显式`--no-include-caves`、`--no-approximate-gate`和`--no-optimize-player-y`可关闭配置中的开关。

线程数默认等于`std::thread::hardware_concurrency()`（当前机器的硬件并发度），多核机器会吃满全部核心；取不到硬件信息（该函数返回0）时退回16。校验上限为1024，只用于拦截荒谬输入。结果与线程数无关（逐位一致），线程数只影响耗时；需要固定复现耗时对照时显式传`--threads`。注意每个工作线程在精算阶段会同时持有一个约12MB的1:1窗口（半径128），线程数很大时应结合本机内存评估。

直接调用用`riverfinder_native::Config`和`search`。JSON适配的内部字段使用驼峰：

```json
{
  "seed": "12345",
  "version": "26.3",
  "radius": 100000,
  "coverage": "game",
  "includeCaves": true,
  "yMin": -63,
  "yMax": -51,
  "playerY": -40,
  "pureRiverMaskStep": 64,
  "approximateGate": true,
  "simulationDistanceChunks": 10,
  "candidateBudget": 8192,
  "minDistance": 256
}
```

自由矩形用`"rectMode": true`加`minX/maxX/minZ/maxZ`；三字段用`minRiverArea/minCaveArea`。非法组合在启动时报错。

JSONL入口仍为`--desktop`、protocolVersion=3。start.config保留finder/seed/bounds/threads/resultLimit/deferExport，params接受mcVersion及上述农场字段，去掉seed/version/radius；`bounds`可带`rect`对象。未知参数拒绝。旧sampleY/caveFactor不兼容，需要桌面后续适配。

结果返回模型`drowned-weighted-area-v2`、实际归一化配置、理论系数、四分权重`quartWeights`、三字段门槛`minimumArea`、`warnings`及源码身份。候选带score、精确分子字符串scoreNumerator、分母scoreDenominator、riverArea、riverVolume、caveVolume、bestPlayer XYZ。riverArea是游戏几何裁剪后yMin层的有效河流格数，不代替全部层的主评分。

顶层还带 `playerYSource`（`auto` / `fixed` / `platform`）与 `fullShellArea`：后者是显示分母，等于各层 24–128 球壳格数之和除以层数（默认窗口 49659），由几何精确推导；`coverage=game` 还会按自然刷怪区块裁剪，所以它只是上界。

进度分coarse/refine，各自百分比独立，不在粗筛结束伪造整体100%。scannedTiles/totalTiles是任务分块数，50万及以上采用8192格块，其余为2048格块；如发生补扫会累计两趟。biomeCells是采样输出格位；都不是全世界区块数。biomeWorkerMs和geometryWorkerMs为线程累计耗时，不能与阶段墙钟直接相加；coarseMs包含暂停。exportMs记录文本准备／写入，不包含最终JSON自身落盘。cacheBuildMs为周期表构建墙钟时间；quartWorkerMs／preciseWorkerMs分别是初步细排和最终窗口采样的线程累计时间；refinedCandidates包含两阶段窗口次数，不等于不同热点数。进度阶段序列为`prepare → coarse → refine → report → done`，各阶段百分比独立；每个阶段末帧必发，粗筛一定会显示到100%再切精排。运行中每帧带`speedPerSecond`、`etaMs`、`scannedChunks`与`overallPercentage`。

CSV/TXT/JSON使用同一最终榜单和后端评分，排名为主评分降序、距搜索中心距离升序、X/Z升序。热点最小间距默认256格，取消不返回正常完成。只有同进程暂停／继续，没有跨进程断点。

## 验证边界

本地回归覆盖朴素几何穷举、平台挂机Y、单位、排序、热点去重、CLI/JSONL、逐格重算、原版冻结参照、批量／单点群系一致性、早退漏斗与全判的一致性（1728000点）、weird早退漏点预算，以及 core/ 的许可证扫描。常规测试不启动游戏或Java。

当前原版低Y参照为8个版本、单种子、3个3×3×13窗口，共2808格，包含部分高度的河流／洞穴切换与深暗之域。另有32版批量／逐点内部一致性检查；不能称为32版全部原版生成均已验证。

早退漏斗是有损近似门（C1 分级后）：大陆性 10 个八度 ≤0.525 直接判否，门附近约 0.3% 的点会与全判翻转（掩膜随后做 1 格膨胀兜底）；0.525~0.575 之间仍补算全部 18 个八度，>0.575 才跳过（剩余八度的实测最大影响远小于 0.05，不引入额外差异）。weird 约 3e-6。`--no-approximate-gate` 下与改造前逐格一致（26.3与1.21各20名对照完全相同）。

用户恢复供电后已重新授权测速。实际参数、结果和未完成的大范围验证见[开发记录](../记录/开发记录.md)。
